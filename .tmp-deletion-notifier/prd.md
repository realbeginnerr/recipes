## 1. 제품 정의

UX/UI 디자인, 개발, AI 툴, 마케팅을 공부하는 사람이 낯선 용어의 의미를 이해하고 기억하도록 돕는 플래시카드 웹사이트다. 누구나 로그인 없이 용어 카드를 학습할 수 있다. 관리자가 승인한 이메일 계정으로 로그인한 사용자는 이해도와 학습 진행 상황을 저장하고 마이페이지에서 확인할 수 있다.

영어 철자·번역 암기 서비스가 아니다. 영문 이름이나 약어는 개념을 식별하고 검색하기 위한 보조 정보다. 학습의 중심은 용어의 뜻과 사용 맥락이다.

### 제품 목표

붕억빵을 유용한 용어 학습 서비스로 성장시키고, 관련 분야를 공부하는 사람들 사이에서 웹사이트를 바이럴시킨다.

바이럴 여부는 게시물의 절대 조회수와 해당 계정의 평소 게시물 대비 상대 조회수를 각각 평가한다. 두 기준은 서로 대체하지 않으며, 결과를 기록할 때 어느 기준을 적용했는지 함께 표시한다.

#### 기준 1. 게시물 절대 조회수

| 등급          |            게시물 조회수 | 평가                           |
| ------------- | -----------------------: | ------------------------------ |
| 바이럴 대성공 |             10만 회 이상 | 대규모 확산                    |
| 바이럴 성공   | 1만 회 이상 10만 회 미만 | 상당한 확산                    |
| 바이럴 아님   |              1만 회 미만 | 일반적인 노출 또는 소규모 확산 |

#### 기준 2. 계정별 상대 조회수

평소 게시물의 조회수 중앙값과 해당 게시물의 조회수를 비교한다.

| 등급          | 평소 게시물 조회수 중앙값 대비 |
| ------------- | -----------------------------: |
| 바이럴 대성공 |                      20배 이상 |
| 바이럴 성공   |             5배 이상 20배 미만 |
| 바이럴 아님   |                       5배 미만 |

#### 기준선 자료

- 측정 기간: 2026년 10월 1일~31일
- 한 달간 조회수: 39,062회
- 조회한 사람: 18,941명
- 위 수치는 계정의 월간 현황을 기록한 기준선 자료다. 기준 2를 계산할 때는 별도로 수집한 평소 게시물별 조회수의 중앙값을 사용한다.

## 2. 사용자와 문제

### 대상

- 운영자 본인 및 해당 분야를 공부하는 누구나 이용한다.
- 입문자, 취업 준비생, 현직자 모두 포함한다.
- 경력의 주니어·시니어 구분을 학습 자격이나 기본 난이도의 기준으로 사용하지 않는다. 경력이 있어도 새 분야와 개념은 낯설 수 있다.
- 모바일 이용을 우선하며 PC에서도 같은 핵심 기능을 제공한다.

### 해결할 문제

- 공부 도중 낯선 용어가 자주 등장한다.
- 설명을 읽었어도 시간이 지나면 기억나지 않는다.
- 어떤 용어를 모르는지 따로 관리하기 번거롭다.
- 학습 전에 가입하거나 복잡한 설정을 하는 부담이 있다.

### 핵심 가치

짧게 뜻을 떠올리고 확인하며, 모르는 용어만 모아 반복한다. 사용자가 스스로 공부할 수 있도록 차분하고 단순한 경험을 제공한다.

## 4. MVP 범위

아래 세부 동작은 최소 구현을 위한 제안이다. 확정된 범위를 확대하는 기능은 별도로 표시한다.

| ID   | 기능             | 요구사항                                                                                 | 근거·상태                  |
| ---- | ---------------- | ---------------------------------------------------------------------------------------- | -------------------------- |
| F-01 | 학습 시작        | 가입 없이 바로 학습 가능                                                                 | 확정                       |
| F-02 | 분야 선택        | 전체 또는 다섯 분야 중 하나를 골라 학습                                                  | 확정                       |
| F-03 | 카드 앞면        | 한글 용어명과 영문·약어를 함께 표시. 영문이 없으면 한글만 표시하고 동일 표기는 중복 생략 | 확정                       |
| F-04 | 카드 뒷면        | 용어의 정의와 보유한 설명·예시 표시                                                      | 뒤집기 확정, 구성 제안     |
| F-05 | 이해도 표시      | 설명 확인 후 ‘알아요 / 몰라요’ 선택                                                      | 표시 기능 확정, 2단계 제안 |
| F-06 | 복습             | ‘몰라요’인 용어만 모아 다시 학습                                                         | 확정                       |
| F-07 | 기록 유지        | 로그인 계정의 이해도와 분야별 완료 묶음을 Firestore에 저장                               | 확정                       |
| F-08 | 관리자 인증      | 운영자 본인 Google 계정으로 로그인·로그아웃                                              | 확정                       |
| F-09 | 사용자 인증      | 관리자가 Firebase에 사전 등록한 이메일로 로그인, 최초 비밀번호 설정, 이메일 인증, 로그아웃 | 확정                       |
| F-09 | 용어 관리        | 용어 목록 조회 및 등록·수정·삭제                                                         | 확정                       |
| F-10 | 초기 데이터 반영 | CSV 238개 검토·변환·등록                                                                 | 확정, 파일 구조 확인 필요  |

용어 검색, 즐겨찾기, 공개·비공개 전환, 통계 대시보드는 MVP 필수 기능에 넣지 않는다. 필요성이 확인되면 별도 범위로 검토한다. 관리자 목록에서는 약 238개 중 수정 대상을 찾을 수 있도록 간단한 용어명 검색을 제안한다.

## 5. 사용자 흐름과 학습 정책

### 일반 학습

1. 첫 화면에서 전체 또는 분야를 선택한다.
2. ‘학습 시작’을 누른다.
3. 카드 앞면의 용어를 보고 의미를 떠올린다.
4. ‘설명 보기’를 눌러 뒷면을 확인한다.
5. ‘알아요’ 또는 ‘몰라요’를 선택한다.
6. 이해도가 저장되고 다음 카드 앞면으로 이동한다.
7. 최대 10장의 회차가 끝나면 완료 화면을 표시한다. 선택 범위에 카드가 더 있으면 다음 묶음으로 이어간다.

### 모르는 용어 복습

1. 첫 화면의 ‘모르는 용어 복습’을 누른다.
2. ‘몰라요’인 카드만 학습한다.
3. ‘알아요’로 바꾸면 이후 복습 대상에서 제외한다.
4. ‘몰라요’를 다시 선택하면 이후 복습 대상으로 유지한다.
5. 복습할 카드가 없으면 빈 상태와 일반 학습으로 가는 행동을 제공한다.

### 세부 동작 제안

- 상태는 ‘미학습 / 알아요 / 몰라요’로 관리한다. 미학습은 자동 상태이며 평가 버튼은 두 개다.
- 일반 학습의 전체 대상은 해당 범위의 모든 유효한 용어이며, 한 회차에 최대 10장씩 학습한다. 과거 이해도 평가로 일반 학습 대상을 숨기지 않는다.
- 카드 순서는 초기 원본 순서로 시작한다. 무작위 섞기는 MVP 필수 기능이 아니다.
- 한 회차는 시작 시 대상 ID 목록을 고정한다. 같은 회차에서 ‘몰라요’ 카드를 즉시 반복시키지 않는다.
- 평가하지 않고 이탈하면 해당 카드의 이전 상태를 유지한다.
- 평가 버튼은 카드 앞면과 뒷면 모두 카드 아래 같은 영역에 제공한다. 뒤집기 전에도 평가할 수 있으며 중복 터치로 여러 카드가 넘어가지 않게 한다.
- 현재 카드 번호와 회차 전체 수를 표시한다. 이는 이해도나 시험 점수가 아니다.
- 재방문 시 이해도는 유지하지만 중단한 회차의 정확한 위치 복원은 MVP 필수 기능이 아니다.
- 설명이 길어도 자르지 않고 읽을 수 있게 한다. 뒤집기 때문에 스크롤이나 내용 선택이 방해받지 않아야 한다.
- 복습 중 범위는 우선 전체 분야로 제안한다. 분야별 복습 필터는 추가 필요성을 확인한다.

### 10장 단위 학습 세부 설계

사용자가 확정한 수량을 실행 가능한 흐름으로 만든 설계다. 아래 이어보기·순환 방식은 구현을 위한 기본안이며 수량·이름·표시 방식과 구분한다.

- 일반 학습과 복습 모두 한 회차 최대 10장이다. 남은 카드가 10장 미만이면 남은 수만 표시한다. 카드가 없으면 빈 상태를 표시한다.
- 일반 학습은 선택 분야의 원본 순서를 따르고, 회차가 끝나면 ‘다음 10장 학습’을 제공한다. 마지막 묶음은 실제 수량을 표시한다. 전체 239개라면 마지막 회차는 9장이다.
- 같은 분야를 계속 학습할 때 매번 첫 10장만 반복하지 않도록, 완료한 묶음의 카드 ID를 분야별 진행 정보로 계정 저장소에 저장한다. 전체 분야와 각 분야의 진행 정보는 별도이며 이해도는 공통 카드 ID로 공유한다.
- 회차를 중단하면 평가한 이해도는 유지하지만 완료한 묶음으로 처리하지 않는다. 재진입 시 해당 묶음을 앞에서 다시 시작할 수 있으며 정확한 카드 위치 복원은 보장하지 않는다.
- 선택 분야의 전체 대상을 한 번씩 보면 ‘이 분야를 한 바퀴 학습했어요’와 ‘처음부터 다시 학습’을 제공한다. 다시 학습은 묶음 진행만 새로 시작하며 알아요·몰라요 기록을 지우지 않는다.
- 복습은 시작 시 몰라요인 카드 ID를 고정해 10장씩 나눈다. 같은 복습 흐름의 다음 묶음에는 아직 보지 않은 대상만 포함한다. 마지막 묶음 이후 최신 몰라요 목록을 다시 계산해 재복습할 수 있다.
- 이번 회차 몰라요 복습은 해당 회차에서 몰라요로 평가한 유효한 카드만 대상으로 하며 최대 10장이다.
- 로컬 진행에 남아 있는 삭제된 카드 ID는 제외한다. 새 카드는 원본 순서 뒤쪽에 추가하며, 숫자 인덱스만으로 진행을 추적하지 않는다.
- 앞면에서 영문·약어가 없으면 빈 줄을 만들지 않는다. 한글명 칸과 영문 칸이 Git·n8n처럼 같은 표기라면 한 번만 보여준다. 영문 이름만 있는 용어에 임의 한글명을 만들지 않는다.

## 6. 화면 구성

| 화면             | 핵심 내용과 행동                                                          |
| ---------------- | ------------------------------------------------------------------------- |
| 첫 화면          | 서비스 목적 한 줄, 분야 선택, 학습 시작, 모르는 용어 복습과 대상 수       |
| 학습 화면        | 분야, 현재 순서, 용어 카드, 설명 보기/용어 보기, 이해도 버튼, 학습 종료   |
| 완료 화면        | 이번 회차에서 평가한 수와 ‘몰라요’ 수, 모르는 용어 복습, 첫 화면으로 이동 |
| 관리자 로그인    | 운영자 인증, 실패 안내                                                    |
| 관리자 용어 목록 | 용어명·분야, 추가·수정·삭제 진입, 용어명 검색 제안                        |
| 관리자 편집      | 필수·선택 필드 입력, 저장·취소, 필드별 오류                               |

별도 홍보 랜딩 페이지와 복잡한 메뉴 구조는 필수로 두지 않는다. 첫 진입 화면에서 학습 행동이 먼저 보이게 한다.

## 7. 용어 콘텐츠와 초기 엑셀

### 데이터 구조 제안

| 필드                  | 필수 여부   | 용도                                                             |
| --------------------- | ----------- | ---------------------------------------------------------------- |
| id                    | 시스템 필수 | 내용이 바뀌어도 유지되는 고유 식별자                             |
| term                  | 필수        | 용어명                                                           |
| categories            | 필수        | UX/UI 디자인·피그마·개발·AI 툴·마케팅 중 하나 이상. 복수 분야 허용 |
| definition            | 필수        | 짧고 이해하기 쉬운 한국어 정의                                   |
| englishTerm           | 선택        | 영문 표기·약어                                                   |
| explanation           | 선택        | 추가 설명                                                        |
| example               | 선택        | 사용 맥락을 보여주는 예시                                        |
| source                | 선택        | 의미 검수용 참고 출처                                            |
| createdAt / updatedAt | 시스템 필수 | 생성·수정 시각                                                   |

사용자가 승인한 정리 작업에 따라 복수 분야 분류 초안을 작성했다. 최종 분류는 검토안 5장 전체 통과로 사용자 승인 완료다. 같은 카드가 여러 분야에 속해도 전체 학습과 복습에서는 ID 기준 한 번만 포함하고 이해도를 공유한다. 없는 예시·영문·출처를 임의로 만들어 채우지 않는다. 피그마 기능·UI·작업 개념에 해당하는 기존 용어 46개에는 기존 분야를 유지하면서 `피그마` 분야를 추가한다.

### 콘텐츠 작성 원칙

- 설명은 한국어 중심으로 작성하고 영문·약어는 필요한 경우 함께 보여준다.
- 경력 수준을 단정하거나 사용자를 평가하는 문구를 사용하지 않는다.
- AI 툴 용어는 일반 사용자의 이해와 활용에 필요한 수준으로 설명한다. 엔지니어링 심화 과정을 기본 범위로 삼지 않는다.
- 특정 도구에서만 사용하는 용어는 해당 맥락을 표시해 보편 정의로 오해하지 않게 한다.
- 기존 엑셀 원문을 보존하고, 의미 변경이 필요한 경우 운영자 검수를 거친다.

### 초기 데이터 반영 절차

1. 확인된 원본은 UTF-8 CSV이며, 2개 헤더 레코드와 용어 238개가 있다. 빈 레코드 13개와 실제 값이 없는 후행 열은 카드로 변환하지 않는다.
2. CSV의 한글 용어·영문명·한글 뜻을 서비스 필드에 매핑한다. 기존 분야 표시는 원문으로 보존하고, 새 categories는 별도로 검토한다. 시험일·실무 언급량·영문 정의·비고는 원문 자료로 보존하며 무조건 공개하지 않는다.
3. 필수값 누락·중복 후보·분류 불일치를 목록으로 정리한다.
4. 운영자가 확인한 데이터에 안정적인 ID를 부여한다.
5. 등록 예정 건수와 오류를 검토한 뒤 초기 데이터로 반영한다.
6. 원본 대비 건수와 주요 필드가 보존되었는지 확인한다.

초기 일괄 반영은 데이터 준비 작업이다. 운영자가 반복 사용하는 엑셀 업로드 화면은 MVP 필수 기능이 아니다. 동일 파일을 재처리해 중복 등록하지 않도록 반영 이력을 관리한다.

## 8. 기록 저장과 데이터 변경

- 용어 콘텐츠는 모든 방문자에게 같은 최신 데이터를 제공한다. 개인 이해도와 분야별 완료 기록은 로그인 계정 전용 Firestore 경로에 저장한다.
- 로컬 기록은 용어 ID별 이해도와 저장 형식 버전을 최소 구조로 사용한다.
- 비회원의 알아요·몰라요와 진행 상황은 현재 페이지 메모리에만 유지하며 새로고침·종료 후 복원하지 않는다. 회원 기록의 정식 원본은 계정별 Firestore 문서다.
- 로컬 저장이 실패하면 현재 회차 학습은 가능하게 하고, 기록을 유지할 수 없다는 안내를 제공한다. 저장 성공으로 오인시키지 않는다.
- 기록이 손상된 경우 자동으로 전체 기록을 덮어쓰지 않는다. 복구 가능한 항목을 우선 읽고 필요하면 초기화 선택을 안내한다.
- 관리자가 용어를 수정해도 ID는 유지한다. 기존 이해도는 유지하는 것을 기본 제안으로 한다.
- 삭제된 용어의 로컬 기록은 학습·복습 수에 포함하지 않는다. 이후 정리할 수 있다.
- 네트워크 요청 실패를 ‘용어 0개’나 ‘복습 완료’로 표시하지 않는다. 재시도 행동을 제공한다.
- 오프라인 이용 보장은 MVP 범위에 포함하지 않는다.

## 9. 관리자 요구사항

- 일반 사용자용 가입·로그인과 구분된 관리자 진입 경로를 제공한다.
- 운영자 본인으로 허용된 계정만 관리 작업을 수행할 수 있다. 로그인 성공 자체를 관리자 권한으로 간주하지 않는다.
- 화면과 데이터 저장 계층에서 모두 권한을 확인한다. 비로그인·비관리자의 직접 쓰기 요청도 거부한다.
- 관리자 인증은 Google 로그인을 사용하고, 운영자 본인 계정만 관리자 권한을 부여한다. 로그인 유지 정책은 구현 전 확정한다. 비밀번호·비밀키를 프런트엔드에 포함하지 않는다.
- 일반 사용자는 공개 회원가입을 할 수 없다. 관리자가 Firebase Authentication에 이메일 계정을 먼저 등록한 사람만 로그인할 수 있다.
- Firebase 비밀번호는 최소 6자이므로 최초 비밀번호 `0000`은 사용하지 않는다. 관리자는 임시 비밀번호를 사용자에게 공유하지 않고, 사용자가 로그인 화면의 ‘최초 비밀번호 설정·재설정’ 메일을 통해 본인 비밀번호를 직접 만든다.
- 이메일 인증을 완료하지 않은 계정은 로그인 상태를 유지하지 않으며, 인증 메일을 다시 보낸 뒤 로그아웃한다.
- 마이페이지에서 이메일, 학습한 용어 수, 알아요·몰라요 수, 비밀번호 변경, 로그아웃, 계정 삭제 요청을 제공한다.
- 계정 삭제 요청 전 약 1일의 처리 기간과 계정·암기 기록을 복구할 수 없다는 점을 명확히 안내한다. 요청은 Firestore 관리자 이메일 알림 대기열에 등록한다. Google Apps Script가 한국 시간 기준 매일 오전 9시와 오후 9시 근처에 미처리 요청을 확인해 관리자 이메일로 알리고 발송 시각을 기록한다. 관리자는 요청을 직접 확인한 뒤 Firebase Authentication 계정과 해당 사용자의 학습 기록을 삭제한다.
- 저장 전 필수 필드와 분야 값을 검증한다. 실패하면 입력을 유지하고 수정·재시도가 가능해야 한다.
- 저장 성공 후에만 완료 안내를 표시한다.
- 삭제 전 대상 용어를 명시해 확인한다. 취소하면 변경하지 않는다. 삭제 실패를 성공으로 표시하지 않는다.
- 저장하지 않은 편집 내용을 버리고 이탈하려는 경우 확인한다.
- 사용자 입력은 실행 가능한 HTML·스크립트로 처리하지 않는다.

## 10. UX/UI와 디자인 시스템 적용

### 디자인 기준 문서

- 진입점: [기존 디자인 시스템](../../recipes/docs/design-system.md)

공통 디자인 규칙을 재사용한다. 기존 명세에는 레시피 전용 정책을 다른 사이트에 복사하지 않도록 명시되어 있으므로 레시피 메뉴·사진·영양 정보·목록 열 수는 이 서비스의 기준으로 사용하지 않는다. 확정된 플래시카드 전용 토큰은 별도 프로젝트 설정으로 관리한다.

타이포그래피는 다음 우선순위를 적용한다.

1. Carbon Design System의 역할 기반 타입 토큰과 productive·expressive 사용 원칙을 우선한다. 학습 카드·선택 목록·버튼·폼은 productive, 홈의 소개 제목은 expressive 타입을 사용한다.
2. Carbon이 지원하지 않는 한글은 기존 레시피 디자인 시스템의 Pretendard로 대체한다. 영문·숫자는 IBM Plex Sans, 코드 표시는 IBM Plex Mono를 우선한다.
3. 글자 크기·행간·자간·굵기는 임의 값을 추가하지 않고 프로젝트의 Carbon 대응 CSS 변수로 관리한다. 본문·레이블·버튼·제목 등 같은 역할은 같은 토큰을 사용한다.
4. 브랜드색 `#255A46`, 각진 버튼과 기존 표면 색상은 레시피 디자인 시스템에서 재사용한다.

### 화면 원칙

- 모바일에서 한 장의 카드와 현재 행동에 집중한다.
- 차분한 정보 위계와 읽기 편한 한국어를 사용한다. 랭킹·연속 출석·과도한 보상 연출은 MVP에 넣지 않는다.
- 긴 정의와 예시는 자연스럽게 늘어나게 하고 고정 높이로 잘라내지 않는다.
- 이해도는 색상뿐 아니라 텍스트로 구분한다.
- 터치 조작을 우선하고, 스와이프를 필수 조작으로 삼지 않는다.
- 버튼은 키보드와 보조기기로 조작할 수 있고 현재 포커스를 확인할 수 있어야 한다.
- 뒤집기 애니메이션을 사용하더라도 짧게 처리하고 움직임 감소 설정을 존중한다.
- 모바일 화면 폭, 글자 확대, 긴 용어, 긴 설명, 빈 데이터, 로딩·오류 상태를 확인한다.

## 11. MVP 제외 및 추후 검토

아래는 사용자가 향후 검토를 요청한 항목이다. 이번 출시의 개발·완료 기준에 포함하지 않는다. 도입 순서는 미정이다.

| 기능               | 향후 검토 내용                                     | MVP에서의 대안           |
| ------------------ | -------------------------------------------------- | ------------------------ |
| 객관식 퀴즈        | 선택지 작성·검수, 정답 해설, 오답 처리             | 카드 뒤집기와 자기 평가  |
| 주관식 퀴즈        | 정답 허용 범위, 유사 표현, 채점 방식               | 뜻을 떠올린 뒤 설명 확인 |
| 간격 반복 학습     | 복습 일정, 이해도별 간격, 재평가 정책              | ‘몰라요’ 목록 수동 복습  |
| 학습 기록 내보내기 | 파일 형식, 버전, 포함 정보                         | 계정 저장 기록 활용      |
| 학습 기록 가져오기 | 형식 검증, 기존 기록 병합·덮어쓰기, 삭제된 ID 처리 | 계정 저장 기록 활용      |

AI 자동 설명 생성, 결제, 커뮤니티는 MVP 범위에 포함하지 않는다. 이 항목들은 사용자 요청으로 확정된 향후 기능은 아니다. 기기 간 동기화는 별도 기능·화면·홍보 항목으로 제공하지 않는다.

## 13. MVP 성공 판단

- 사용자가 별도 설명 없이 첫 카드를 보고 이해도를 표시할 수 있는가.
- 재방문 시 모르는 용어를 찾아 복습할 수 있는가.
- 운영자가 개발자 도움 없이 개별 용어를 등록·수정·삭제할 수 있는가.
- 초기 사용자 관찰로 학습 흐름의 막힘과 설명의 이해 가능성을 확인한다. 자기 평가 수치를 실제 지식 습득의 증명으로 취급하지 않는다.
- 바이럴 성과는 1장의 절대 조회수·계정별 상대 조회수 기준으로 판단한다. 방문·학습 시작·학습 완료 등의 이용 흐름은 Amplitude를 연결해 측정한다. 방문→학습 시작 전환율의 구체적인 수치 목표는 실제 운영 데이터를 축적한 뒤 정하며, 성과 측정을 이유로 일반 사용자 계정을 추가하지 않는다.

## 15. 초기 CSV 필드 매핑과 검수 상태

| 원본 열                       | 사용 계획                                                         |
| ----------------------------- | ----------------------------------------------------------------- |

| 시험일 / 실무 언급량·기본상식 | 기존 학습 자료 메타데이터로 보존, 일반 사용자 화면 노출 제외 제안 |

- [검토 문서](glossary-review.md)와 [정리 JSON 초안](../data/glossary-draft.json)을 작성했다.
- 병합 5쌍과 디자인/개발 라이브러리 별도 유지는 사용자 승인 완료. 원본 11행은 사용자 문구로 어피니티 다이어그램·카드 소팅 두 카드로 분리하고, 151행 IA 검증기는 카드 목록에서 삭제했다.
- 원본 238개에서 병합 -5개, 기존 분리 +1개, 삭제 -1개, 이번 첨부의 개념 분리 +6개로 현재 카드는 239개다. 원본 238개 행은 삭제 이력을 포함해 모두 추적 가능하다. 나머지 검토 사항은 대기 상태다.
- 전체 정의를 검수·수정한 것은 아니다. 의미 불일치·오표기 의심 항목은 검토 문서에 기록했다.
- 154행 스킬: AI에게 작업 방법을 알려주는 지침 묶음으로 설명하고 AI 툴 분야로 분류한다. 폴더 구조는 예시이며, 모든 AI 도구가 이 구조를 똑같이 사용하는 것은 아님을 명시한다. 사용자 승인 완료.
- 원본 CSV·운영 데이터는 변경하지 않았다.

- 사용자 승인된 첨부 내용 검토와 정확성 조정은 [검토안 7장](glossary-review.md#section-7)에 기록했다. AI 제품/모델, Tap/Tab, 변수/상수, 디자인·AI·접근 토큰, 행동 맵핑/평행좌표를 구분하고 원문 추적 정보를 유지한다.
- 어셈블리어·PaaS·IaaS·PR·n8n·Make·ER·터미널·샌드박스 9개 정의·예시는 [검토안 8장](glossary-review.md#section-8)에 제안했다. 해당 정의·예시·표기는 사용자 승인 완료이며 운영 데이터에는 반영하지 않았다.

- 2026-11-16: 사용자가 검토안 7·8장을 통과 처리했다. 해당 내용·개념 분리·정의·예시·표기를 승인 완료로 기록했다. 전체 239개 카드와 분야 분류를 일괄 승인한 것으로 해석하지 않는다.

- 2026-11-16: 사용자가 검토안 5장 전체를 통과 처리했다. 전체 239개 카드의 분야 분류와 복수 분야 배정을 확정한다. 카드 정의·예시는 이번 승인으로 변경하지 않으며 기존 승인 범위를 유지한다.
