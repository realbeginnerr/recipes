## 1. 문서 역할과 적용 범위

- 이 문서는 tsrecipe에서만 사용하는 디자인 선택과 기능별 결정 사항을 관리한다. 다른 사이트에 공통 규칙으로 복사하지 않는다.
- 공통 컴포넌트·접근성·오류 복구·스크롤·모션 원칙은 [범용 디자인 시스템](design-system.md)을 참조한다. 같은 내용을 이곳에 반복하지 않는다.
- 범용 문서의 토큰은 재사용용 프리셋이다. 토큰 변경만으로 tsrecipe의 글꼴·색상·레이아웃을 바꾸지 않는다. 사이트의 실제 값은 아래 설정과 연결된 소스에서 확인한다.
- 최근 사용자가 명시한 변경과 기존 승인 정책을 구분해 반영한다. 레시피 기능의 기존 승인 정책 원본은 [PRD 11장](requirements.md#11-레시피-메뉴-검토--승인된-정책)이다.
- 아래 현재 구현 설명은 정리일의 로컬 작업 트리를 정적으로 확인한 결과다. 운영 배포·실제 브라우저·모바일 검증이 끝났다는 뜻은 아니다.
- 소스와 승인 정책이 다르면 8장에 차이를 기록한다. 차이를 발견했다는 이유로 정책을 임의로 폐기하거나 제품 코드를 자동으로 변경하지 않는다.
- 현재 디자인 정비의 우선 목표는 디자인 시스템과 실제 UI의 차이를 찾아 맞추는 것이다. 기존 화면의 스타일을 복사하거나 등록·수정 폼을 통합한 것만으로 준수 검증을 완료하지 않는다. 간격은 Carbon 기준의 수치뿐 아니라 요소 간 관계·정보 계층·중복 여백까지 확인하고, 승인된 프로젝트 예외와 구분해 보고한다.

## 2. 브랜드와 사이트 구성

### 브랜드와 프로젝트 설정

- 서비스명은 T's Recipe다. 음식 사진과 레시피가 중심이며, 영양 계산과 재료 조절은 요리를 돕는 정보로 배치한다.
- 주요 브랜드색은 `#255A46`, 기본 본문 배경은 흰색, 보조 표면은 `#F6F5F1`, 푸터 배경은 `#0D1F19`를 사용한다.
- 큰 제목은 Pretendard, 한국어 본문은 Pretendard 계열, 영어 본문과 독립된 영양·중량 수치는 Inter를 기준으로 한다. 실제 적용 경로는 7장의 스타일 파일을 참조한다.
- 이미지 프레임과 버튼은 각진 모서리를 기본으로 한다. 배지·입력창·기타 표면은 해당 역할의 설정을 따른다.
- 공통 헤더 높이는 64px다. 로고를 누르면 홈으로 이동하므로 별도의 ‘홈’ 메뉴를 두지 않는다.
- 현재 주 메뉴 순서는 레시피 → 식재료 → 캘린더 → 자료실이다. PC·모바일이 같은 메뉴 목록을 사용한다.
- ‘내일 뭐먹지?’와 Shop은 현재 네비게이션에 표시하지 않는다. 해당 페이지·기능을 삭제한 것은 아니다.
- 외부 Contact와 관리자·언어 전환은 헤더에서 제공한다.
- 홈에서는 푸터를 숨기고, 다른 페이지에서는 기존 푸터를 유지한다. 푸터는 저작권 문구를 가운데 표시한다.

### 본문과 카드 배치

- 레시피·식재료·캘린더·자료실의 본문은 최대 1200px와 공통 gutter를 사용한다. 배경 자체는 전체 너비를 사용할 수 있다.
- 공통 gutter의 기준은 모바일 16px, 태블릿 24px, 데스크톱 32px다.
- 레시피 목록은 모바일 2열, 1024px 이상에서 4열을 사용한다. 목록 카드 사진은 정사각형이며 모바일에서는 구체적인 탄단지 g 수치를 숨기고 한 끼 열량을 표시한다. 탄단지 비율은 표시하지 않는다.
- 식재료 카드 목록은 모바일 2열·간격 12px이며, 1024px 이상에서는 5열을 사용한다. 목록 모드의 표에는 이 카드 배치를 적용하지 않는다.
- 기본 소개 헤더는 관련 페이지의 공용 구성을 따른다. 캘린더·자료실은 레시피 목록과 같은 배경 사진을 사용하고 제목 아래 소개 문구를 두지 않는다.

## 3. 페이지별 표시와 동작

### 홈

- 홈은 사진 히어로와 기존 이야기 섹션을 표시한다. 번호가 있는 이야기 섹션은 01–05다.
- 별도로 추가했던 영상 애니메이션 섹션은 홈에서 제거했다. 기존 이야기 섹션은 다시 표시한다.
- 제목과 설명 등 편집 가능한 홈 문구는 `src/i18n/about.ts`를 기준으로 한다. 문구를 이 문서에도 복제해 두 곳에서 관리하지 않는다.
- 홈의 콘텐츠별 배치와 사진은 `AboutPage`, `StorySection`, `StorySplit`에서 관리한다.

### 레시피 목록

- 정적 레시피와 Firestore 레시피를 병합한다. 삭제 상태와 일반 방문자의 숨김 레시피 제외를 유지한다.
- 검색·분류·정렬을 제공한다. ‘차’ 필터 칩은 별도로 표시하지 않고, 기존 ‘차’ 분류는 ‘음료’ 필터에 포함한다. 저장된 분류 값을 일괄 변경하는 정책은 아니다.
- 최근 요리순 정렬은 최신 요리 날짜를 사용한다.
- 목록의 더 보기·복귀 상태에 관한 승인 정책과 현재 구현의 차이는 8장을 따른다.
- 목록 카드는 상세 페이지로 연결되는 링크로 구현한다. 레시피 목록은 현재 열 수 × 3행을 처음 표시하고, ‘더 보기’를 누를 때 같은 수량을 추가한다. 스크롤만으로 자동 추가하지 않는다.

### 레시피 상세와 수정

- 상세의 기본 화면에는 별도의 뒤로가기·목록 복귀 버튼을 두지 않는다. 브라우저의 기본 뒤로가기를 사용한다.
- ‘재료 꺼낼 때’는 냉장실 → 냉동실 → 실온보관 → 미지정 순으로 묶고 빈 그룹은 숨긴다. 그룹 내부는 저장된 재료 순서를 유지한다.
- ‘요리할 때’는 레시피에 지정한 요리 그룹별로 묶는다. 빈 그룹명은 ‘기본 재료’다. 저장한 그룹 순서를 우선하고 새 그룹은 끝에 추가한다.
- 요리 그룹 안에서는 실제 중량이 많은 순서로 표시한다. 단위가 다르면 g 환산값으로 비교하고, 동량은 기존 순서를 유지한다. 환산할 수 없는 재료는 비교 가능한 재료 뒤에 두며 기존 순서를 유지한다.
- 보기 전환으로 수량·단위·영양 계산값을 초기화하지 않는다. 화면 정렬은 저장된 재료 순서 자체를 변경하지 않는다.
- 같은 식재료가 여러 행에 들어갈 수 있다. 각 행의 수량·단위·요리 그룹을 독립적으로 유지한다.
- 수정 저장이 성공하면 해당 상세 페이지로 바로 이동한다. 저장 실패 시에는 입력을 유지한다.
- 조리시간은 분 단위로 관리한다. 요리한 날짜는 여러 개를 추가·삭제할 수 있다.
- 조리 단계 입력란은 기본 한 줄 높이로 표시한다. 상세에서는 단계별 완료 표시를 사용할 수 있다.
- 새로 등록과 수정은 `RecipeTable`의 공통 폼을 사용한다. 필드 구성·순서·명칭·배치·입력 방식·간격은 수정 화면을 기준으로 함께 변경하며, 한쪽만 별도로 수정하지 않는다. 등록의 빈 초기값·등록 버튼 문구·삭제 버튼 미노출과 수정의 기존 값·저장 버튼·삭제 버튼은 동작상 필요한 차이다.
- 등록에도 여러 사진·파일 선택·대표 사진 지정, 조리시간, 여러 요리 날짜, 조리 단계, 메모를 제공한다. 저장 실패 시 초안을 유지하고 다시 저장할 수 있도록 처리 중 상태를 해제한다. 등록 성공 후에도 해당 상세 페이지로 이동한다.
- 입력창의 레이블은 컨트롤과 연결하고 수량 입력에는 재료별 접근성 이름을 제공한다. 조회 실패는 빈 결과와 구분하며 재시도 수단을 제공한다.
- 목록·등록·수정의 간격은 [2026-11-10 간격 점검 및 적용 기록](checklist-audits/2026-11-10-results-design-system-spacing.md)을 따른다. 공통 폼에서는 관련 필드 내부 간격과 독립 영역 사이 간격을 구분하고, 인접 영역의 여백을 중복 적용하지 않는다.

**승인된 표시 예외 (2026-11-10)**

- 레시피 목록 개수·관리자 등록 링크 등 사용자가 의도적으로 연하게 만든 텍스트는 대비 조정 대상에서 제외한다. 다른 화면의 텍스트까지 일괄 적용하는 예외는 아니다.
- 레시피 폼의 영양 상태는 기존 색상 표현을 유지하며 별도 상태 문구·아이콘을 추가하지 않는다.
- 재료 삭제의 `✕`·`×` 아이콘은 현재 표현을 유지한다.
- 등록·수정의 재료 추가 팝업에서 검색 결과가 없을 때 표시하는 ‘식재료 추가’ 링크에는 새 탭 안내를 추가하지 않는다.

### 식재료

- 분류와 보관 장소를 구분해 관리한다. 보관 장소는 냉장실·냉동실·실온보관·미지정이다. 지정값이 있으면 이름 기반 추정보다 우선한다.
- 보관 장소 필터를 제공하고, 식재료 필터의 ‘기타’는 마지막에 둔다. 보관 장소가 미지정이면 카드에 해당 장소 칩을 표시하지 않는다.
- 카드의 기준 용량과 단위를 변경하면 실제 함량을 다시 계산한다. 탄수화물·단백질·지방을 비율 대신 각각의 g으로 표시한다.
- 추가·수정은 공통 폼을 사용한다. 추가 화면은 빈 폼이고 삭제 행동은 수정 화면에만 제공한다. 기존 방식 선택·AI 붙여넣기 화면을 다시 만들지 않는다.
- 재료 추가 팝업의 이름은 여러 줄이어도 왼쪽 정렬한다.

### 캘린더

- 월 이동·오늘 이동·날짜 선택을 제공한다. 기준 날짜는 한국 시간으로 계산한다.
- 레시피의 모든 요리 날짜에 해당 레시피를 표시한다. 같은 레시피를 다른 날짜에 반복해 요리한 이력을 유지한다.
- 날짜 칸의 사진은 좌우를 채우고 레시피 이름은 사진 아래에 표시한다. 사진이 없으면 이름을 유지하며 다른 음식 사진으로 대신하지 않는다.
- 날짜 칸에는 최대 3개를 표시하고 나머지는 더 보기로 해당 날짜의 전체 목록을 확인한다. 선택한 날짜의 목록에서도 상세 페이지로 이동할 수 있다.
- 캘린더 자체의 기록 등록·삭제는 별도 요구 전까지 제공하지 않는다. 기록은 레시피 수정 화면에서 관리한다.
- 일반 방문자에게 숨김 레시피를 노출하지 않는다. 요청 실패를 기록 없음으로 표시하지 않는다.

### 자료실

- 게시판 목록·검색·게시글 상세를 제공한다. 분류 필터 칩은 현재 숨김 상태다.
- 자료 등록 버튼은 검색창 오른쪽에 배치하고 관리자 로그인 상태에서만 표시한다.
- 제목·내용·분류와 외부 링크 또는 최대 20MB의 첨부 파일을 등록·수정·삭제할 수 있다.
- 등록 화면에는 뒤로가기 수단을 둔다. 게시글 상세에서 헤더의 자료실 메뉴를 다시 누르면 목록 첫 화면으로 돌아간다.
- 목록 하단에 클릭 방법을 설명하는 별도의 안내 행은 표시하지 않는다.

### 랜덤 메뉴와 Shop

- 랜덤 메뉴 페이지는 `/recipe-roulette`에 유지한다. 현재 메뉴에서는 숨겨져 있다.
- 현재 룰렛은 가로 카드 띠를 4.2초 동안 감속해 선택한다. 최근 당첨 5개를 가능한 범위에서 제외하고 최소 한 후보는 남긴다. 회전 중 중복 실행을 막고 결과는 상세를 새 탭으로 연다.
- 카드 최대 너비는 300px, 사진은 4:3, 카드 간격은 24px다. 카드 영역과 페이지 배경은 `#F6F5F1`이며 제목·뒤로가기 행은 표시하지 않는다. 실행 버튼은 ‘룰렛 돌리기’다.
- 3D 공간형 추천 기능은 계획 검토 단계이며 현재 구현으로 간주하지 않는다.
- Shop 노출과 사진 상품의 임시 운영 정책은 [Shop 중지 기록](shop-status.md)에서 관리한다. 현재 `shopFeatures.enabled`는 `false`다.

## 4. 레시피·식재료와 영양 계산

### 계산 기준

- 한 끼 기준은 탄수화물 60g·단백질 35g·지방 20g, 총 560kcal다. 값은 `src/constants/nutrition.ts`에서 관리한다.
- 영양 합계는 저장된 기준량과 단위 환산을 사용한다. 단위를 바꿀 때 실제 중량과 계산값을 유지한다.
- 유효한 환산값이 없는 단위는 새로 적용하지 않고 안내한다. 레시피 저장 시에도 주재료·부재료의 환산 정보를 확인한다.
- 기준 단위 자체의 설정과 레시피에서의 유효 단위 선택을 구분한다. 계산 불가와 실제 영양 0의 구분은 PRD의 승인 정책과 미해결 항목을 함께 확인한다.
- 단위 환산 입력은 동일한 양의 여러 단위 수량을 나타낸다. 예를 들어 g=100, 컵=1이면 1컵은 100g이다.
- 단위 목록은 `src/constants/ingredientUnits.ts`에서 관리한다. oz·lbs의 g 기반 계산과 ‘선택안함’의 처리도 해당 구현을 따른다.

### 레시피를 식재료로 사용

- 식재료 등록·수정의 공통 폼에서 기존 레시피를 선택해 `sourceRecipeId`로 연결한다. 이름·사진을 가져오며, 보관 장소·분류·별도 단위 환산은 식재료에서 설정한다.
- 레시피 선택 팝업에서 레시피를 고른 뒤 **사용중량(g)**, 즉 이번에 사용할 양을 입력한다. 선택만으로 폼을 변경하지 않고, 팝업 하단의 **확인**을 눌러 식재료 기준량과 해당 양의 영양을 적용한다. **취소**·Escape·배경 클릭으로 닫으면 기존 식재료 초안을 유지한다. 취소 가능한 선택 팝업의 닫기 용어는 ‘취소’로 통일한다.
- 사용중량 입력·확인은 원본 레시피나 저장된 식재료를 직접 쓰지 않는다. 식재료 화면의 저장을 눌러야 식재료에 반영된다. 팝업에서는 완성 중량을 입력받거나 원본에 저장하지 않는다.
- 중량 안내·검증 오류는 해당 입력란과 같은 그룹의 바로 아래에 표시하고 `aria-describedby`로 연결한다. 주의·오류 문구는 빨간색 오류 토큰(`text-destructive`)과 텍스트로 표시한다.
- 원본에 유효한 `finishedWeightGrams`가 이미 있으면 영양 환산에 재사용한다. 없으면 원본 주재료의 g 환산 무게 합계를 기준으로 추정하며, 수분 변화 미반영을 안내한다. 등분 수와 한 끼 보기의 곁들임 부재료는 이 계산에서 제외한다. 완성 중량은 선택의 필수 조건이 아니다.
- 연결 식재료는 100g당 계산값에 사용중량/100을 곱한 탄단지를 저장한다. 다음 조회에서도 `baseAmount`에 저장한 사용중량을 유지하고 그 양에 맞춰 다시 계산한다. 사용중량을 원본 전체 무게의 분모로 사용하지 않는다.
- 영양 정보는 직접 편집하지 않고 원본 레시피를 따른다. 원본 변경 후 다음 식재료 조회 때 재계산하며, 열려 있는 다른 탭의 실시간 동기화는 제공하지 않는다. 서버에 남은 저장 당시 수치만으로 최신 영양을 판단하지 않는다.
- 연결된 레시피를 재료로 쓰는 중첩 계산을 지원하고 순환 연결은 차단한다. 원본 삭제·환산 또는 영양 정보 누락·합산 중량 0 등 계산 불가 상황은 오류로 표시하며 이전 값을 정상적인 최신 값처럼 사용하지 않는다.
- 일반 식재료로 바꾸려면 연결을 해제한다. 원본 레시피는 삭제하지 않는다.

<a id="number-editing"></a>

### 숫자 입력 편집 규칙

Use `src/components/ui/input.tsx` for numeric HTML inputs. While a controlled
number input is focused, it owns the raw editing string, including an empty
string. Parent handlers still receive every change for calculations and
validation, but parsing, clamping and formatting must not replace the text
being edited. On blur, the field displays the parent's committed value using
the existing display precision. Focusing restores its full stored precision.

Do not replace this with a native number input bound directly to a numeric
state value. For forms that require a number before saving, keep raw strings
in the form draft and explicitly reject blank values; the shared Input does
not decide whether blank means zero, missing, or the previous valid value.


### 요리 날짜 이력

- `cookedDates`는 `YYYY-MM-DD` 문자열 배열이며 유효한 날짜만 남기고 중복을 제거해 정렬한다.
- `lastCookedAt`은 가장 최근 날짜로 동기화해 기존 정렬과 호환한다.
- 이전 데이터에 `cookedDates`가 없으면 기존 `lastCookedAt`을 첫 이력으로 사용한다. 명시적인 빈 배열은 전체 이력 삭제를 뜻하며 이전 날짜를 다시 복원하지 않는다.
- 날짜 표시와 배열 정리는 원래 요리 날짜를 시간대 변환으로 다른 날짜로 옮기지 않는다.

### 테이블의 사이트 전용 설정

- 기준 스타일은 `src/components/ui/table.css`다. 행 최소 높이 56px, 셀 패딩 10px 14px, 기본 글자 크기 14px를 사용한다.
- 헤더·보관 장소 그룹은 같은 스타일을 사용한다. 본문은 흰색과 `#FAFAF8`을 교대로 표시하고 그룹마다 흰색부터 다시 시작한다.
- 그룹행 아래에는 별도 선을 두지 않고, 헤더 바로 뒤 첫 행의 위쪽 선은 중복하지 않는다. 합계는 보조 표면·15px·굵기 700으로 구분한다.
- 텍스트·수치는 기본 왼쪽 정렬이며 긴 재료명은 줄바꿈한다. 읽기 전용 숫자는 소수점 첫째 자리까지 표시하고 소수부 0은 생략한다. 계산·저장 원본의 정밀도와는 구분한다.
- 레시피 상세의 재료명 열은 기본 30%를 사용한다. 일반 재료명 열의 과거 최소·최대 너비 정책은 8장의 경계 조건 확인 대상이다.

## 5. 사진과 저장 데이터

- 레시피 `imageUrl`은 대표 URL, `imageUrls`는 추가 URL 배열이다. 사진 ID와 상품 연결 정보가 있는 `images`·`productTags`도 보존한다.
- 레시피 사진은 대표를 포함해 최대 5장, 파일은 장당 10MB 이하로 관리한다. 수정 화면에서 URL 입력·파일 선택·추가·삭제·대표 지정을 지원한다.
- 사진을 모두 제거하면 `imageUrl: ""`, `imageUrls: []`로 저장해 의도적으로 비운 상태를 유지한다. 삭제된 사진을 기본 사진으로 자동 복원하지 않는다.
- 레시피 사진 삭제는 연결 제거다. Storage 원본 파일을 함께 삭제하는 것으로 확대 해석하지 않는다.
- 식재료 `imageUrl`의 빈 문자열도 사진 미등록 상태다. 이미지가 없거나 로딩에 실패하면 공통 미등록 표현을 사용하며 다른 실제 식재료 사진을 대신 넣지 않는다.
- 파일은 Firebase Storage, 레시피·식재료와 자료실 정보는 Firestore를 사용한다. 세부 저장·보안 정책은 서비스 소스와 규칙 파일을 기준으로 별도 검증한다.
- 과거 식재료 ID 연결은 `ingredientCatalogOverrides.ts`와 식재료 로더에서 관리한다. 연결을 보완할 때 레시피의 원래 수량·단위를 임의로 변경하지 않는다.

## 6. 관리자와 외부 연결

- 레시피·식재료 추가·수정과 자료실 작성은 관리자 기능이다. 화면 접근 제한과 Firestore·Storage의 쓰기 권한을 함께 검증한다.
- 관리자는 Firebase Google 로그인을 사용한다. 현재 소스는 `browserLocalPersistence`이며, 창을 닫으면 반드시 로그아웃된다고 안내하지 않는다.
- 관리자 로그인 유지 방식을 바꿀 때는 PRD의 과거 세션 설명과 사용자 의도를 함께 확인한다.
- Contact는 `src/constants/contact.ts`의 외부 주소를 새 탭으로 연다. 과거 ‘티백 소분하기’라는 메뉴명이 현재 표시명인 것으로 취급하지 않는다.
- 한국어·영어 표시 이름·검색·날짜 문구는 현재 언어 설정을 따른다. 번역 표시 때문에 한국어 원문·수량·문서 ID·URL을 덮어쓰지 않는다.
