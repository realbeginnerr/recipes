# 상품 상세페이지 디자인 시스템 — 공통 제작 기준

## 1. 문서 사용 원칙

### 1.1 적용 범위와 제작 방식

- 공통 문서는 판단 기준과 재사용 형식을 정의한다. 실제 상품 설명·고객·수치·원고·색상·제작 폭은 레퍼런스에 기록한다.
- 레퍼런스는 새 상품마다 복사해 작성하는 템플릿이다. 상품군 공통 설정, 개별 상품 정보, 판매 채널 설정을 구분하고 다른 상품의 내용을 누적하지 않는다.
- 제작 시작 전에 **웹 / 이미지형 / 혼합형** 중 방식을 선택한다. 판매 채널과 제작 방식은 별도 항목이다.
- 이미지형은 텍스트를 합성한 이미지 콘텐츠다. 이미지 안의 버튼·탭처럼 보이는 도형은 실제 기능이 없으므로 클릭을 요구하는 조작 UI처럼 만들지 않는다.
- 웹은 HTML 텍스트·실제 컨트롤을 사용한다. 혼합형은 각 부분의 방식을 명시하고 같은 정보를 중복 관리하지 않는다.
- 이미지형의 접근성 한계는 작은 글자 확대나 대체 텍스트만으로 해결됐다고 표현하지 않는다. 채널이 허용하면 핵심 정보를 별도 텍스트로도 제공한다.

### 1.2 우선순위와 예외

- 판매 지역·상품군에 필요한 의무사항과 채널 제한을 먼저 확인한다. 그 범위 안에서 승인된 상품별 예외, 공통 규칙, 참고 예시 순으로 적용한다.
- 예외에는 대상·이유·적용 범위·승인 상태를 적는다. 한 상품의 예외를 전체 공통 규칙으로 확대하지 않는다.
- 확인되지 않은 사항은 `확인 필요`, 제안은 `제안`으로 구분한다. 임시 문구를 확정 사실처럼 납품하지 않는다.
- 웹사이트 관리·데이터 저장·소스 경로·배포 이력은 이 문서에 넣지 않는다.

## 2. 상세페이지 기획과 근거 관리

### 2.1 고객과 핵심 메시지

- 고객이 현재 겪는 상황, 구매 목적, 비교 기준, 구매를 망설이는 이유를 정의한다.
- 주 독자와 보조 독자의 메시지를 구분한다. 한 제목에 서로 다른 고객의 모든 요구를 나열하지 않는다.
- 특징을 고객이 얻을 수 있는 구체적인 쓰임과 연결한다. 결과를 보장하는 표현과 사용 목적을 구분한다.
- 첫 화면에는 상품의 정체·주요 쓰임·핵심 차별점을 우선 보여준다. 전체 설명과 모든 혜택을 몰아넣지 않는다.

### 2.2 주장과 자료

- 레퍼런스에 `주장 → 근거 자료 → 사용 섹션`을 연결해 기록한다. 확인된 사실·제작자 설명·고객 의견을 구분한다.
- 수치·인증·후기·비교·판매량·효율 개선 결과는 실제 근거 없이 생성하지 않는다. 자료가 없으면 주장을 낮추거나 해당 섹션을 생략한다.
- 비교에는 대상·조건·기준·적용 범위를 명시한다. 전후 비교의 차이를 연출로 과장하지 않는다.
- 사진·후기·로고·인용·폰트 등의 출처와 사용 권한을 확인한다. AI 생성 이미지는 실제 제품·결과·고객 증언으로 오인되지 않게 사용한다.
- 상품군별 필수 정보와 구매 조건을 기획 단계에서 수집한다. 제공되지 않은 조건을 임의로 정하지 않는다.

## 3. 콘텐츠 구성과 섹션

### 3.1 흐름과 선택 기준

- 기본 흐름은 관심 → 장점 이해 → 근거 확인 → 구매 불안 해소 → 구매 판단이다. 상품과 고객에 맞게 순서·길이를 조정한다.
- 각 섹션은 독자에게 전달할 **하나의 핵심 메시지**를 중심으로 구성한다. 문장을 하나로 제한한다는 뜻이 아니다. 여러 문장·예시·근거를 사용하더라도 모두 같은 메시지를 뒷받침해야 한다. 독립된 다른 메시지는 별도 섹션으로 나눈다.
- 각 섹션의 텍스트는 **제목 + 추가 설명**으로 구성한다. 제목은 핵심 메시지를 전달하고, 추가 설명은 그 메시지를 구체화하거나 근거를 제시한다. 시각적 위계는 6장을 따른다. 같은 장점을 섹션마다 표현만 바꿔 반복하지 않는다.
- 모듈은 필요한 근거와 자료가 있을 때 선택한다. 후기·비교·FAQ를 모든 상품의 필수 섹션으로 강제하지 않는다.
- 중요한 제한이나 별도 비용을 마지막에 숨기지 않는다. 관련 장점·가격·옵션 가까이에 표시한다.

### 3.2 섹션의 역할

| 모듈 | 답할 질문 | 필요한 자료·선택 기준 |
| --- | --- | --- |
| 첫 화면·대표 비주얼 | 무엇이며 누구에게 필요한가? | 실제 상품명·대표 자료·핵심 메시지 |
| 문제·사용 상황 | 내 상황과 관련 있는가? | 고객 상황의 구체적인 설명, 과도한 불안 조성 금지 |
| 핵심 장점 | 왜 선택할 만한가? | 특징과 쓰임의 연결, 확인 가능한 근거 |
| 사용 장면·사용 방법 | 실제로 어떻게 사용하는가? | 실제 흐름·단계·예시, 필요한 환경 |
| 근거·샘플·비교 | 설명을 믿고 판단할 수 있는가? | 원본 샘플·비교 조건·출처. 자료가 없으면 생략 |
| 후기 | 실제 사용자는 어떻게 평가했는가? | 사용 가능한 실제 후기, 편집 시 의미 보존 |
| 구성·사양 | 정확히 무엇을 받는가? | 포함·미포함 항목, 크기·형식·호환 등 상품군별 정보 |
| FAQ·구매 전 안내 | 구매 전에 무엇을 알아야 하는가? | 실제 예상 질문·제약·확정된 조건 |
| 구매 안내 | 어떻게 선택하고 구매하는가? | 채널의 실제 구매 흐름·가격·옵션·제공 방식 |

## 4. 레이아웃과 간격

- 제작 폭·안전 여백·정렬 기준·텍스트 영역·섹션 간격은 레퍼런스에서 정한다. 배경 전체 폭과 내부 콘텐츠 폭을 구분한다.
- 웹은 실제 화면 너비에 따라 재배치한다. 이미지형은 출력 원본 폭과 모바일에서 축소 표시되는 폭을 구분해 설계한다.
- 같은 역할의 제목·본문·사진은 정렬선을 공유한다. 상품 연출상 다른 구성이 필요하면 의도와 범위를 정한다.
- 간격 값과 관계·그룹화·정보 계층에 따른 선택은 [IBM Carbon Spacing 가이드](https://carbondesignsystem.com/elements/spacing/overview/)를 참고한다. 토큰표와 세부 규칙은 복사하지 않는다. 상세 콘텐츠의 편집 간격은 브랜드와 표시 배율에 맞게 레퍼런스에서 조정한다.
- 가까운 관계와 다른 섹션의 관계를 간격으로 구별한다. 섹션 간격은 한쪽에서 관리하여 위·아래 여백을 중복하지 않는다.
- 구분되는 정보 요소 사이의 실제 간격은 양수로 확보한다. 개별 Margin이 0이어도 최종 간격이 확보되면 허용한다. 사진 이어붙이기 등 간격 0이 필요한 구성은 사용자 승인 예외로 기록한다.
- 공통 여백을 맞추기 위해 제목·주요 사진·중요 안내가 잘리게 하지 않는다. 모바일 실제 표시 크기로 읽기 순서를 확인한다.

## 5. 색상과 시각적 스타일

- 브랜드색·배경·본문·보조 글자·강조·경고의 역할을 구분한다. 실제 색상은 레퍼런스에 둔다.
- 밝고 어두운 배경에 맞는 텍스트를 선택한다. 색상만으로 포함 여부·주의·선택 상태를 전달하지 않는다.
- 장식·그림자·배지·테두리·강조색은 정보 위계를 돕는 수준으로 사용한다. 모든 문장을 동시에 강조하지 않는다.
- 콘텐츠 박스·사진·배지의 라운딩은 역할과 브랜드별로 일관되게 정한다. 웹 컨트롤은 Carbon 컴포넌트별 규격을 기본 참고하며, 콘텐츠 연출까지 동일한 모서리 형태로 강제하지 않는다.
- 실물 색상·재질·구성을 오인하게 만드는 보정과 합성을 피한다. 디지털 상품의 표지 목업은 제공되는 실물로 오인되지 않게 표시한다.

## 6. 타이포그래피와 카피

- 대표 제목·섹션 제목·본문·보조 정보·가격과 조건의 역할별 스타일을 정의한다. 언어별 글꼴·굵기·행간·자간·줄바꿈을 함께 확인한다.
- 공간이 부족하면 문구·줄바꿈·배치를 먼저 조정한다. 중요한 조건을 작은 글씨로 숨기지 않는다.
- 이미지형의 글자 크기는 작업 파일의 수치만으로 판단하지 않는다. 채널에 표시되는 모바일 크기로 본문과 안내를 읽을 수 있어야 한다.
- 섹션 제목은 **크게**, 추가 설명은 **제목보다 작게** 표시하여 위계를 명확하게 만든다. 추가 설명도 모바일에서 읽을 수 있는 크기를 유지한다. 구체적인 크기는 레퍼런스에서 정한다.
- 제목은 3장에서 정한 핵심 메시지를 요약하고, 추가 설명은 같은 메시지의 설명·예시·근거를 맡는다. 추가 설명은 여러 문장이어도 된다. 한 문장에 여러 주장을 몰아넣지 않고 불필요한 전문용어를 줄인다.
- 숫자·단위·가격·날짜의 표기를 통일한다. 구성과 제한은 관련 정보 가까이에 쓴다.
- 매출·작업 시간·성과의 확정적 보장, 확인되지 않은 최상급·희소성·할인 표현을 쓰지 않는다.
- 말투와 용어를 일관되게 사용한다. 사실을 알리는 문장과 제안하는 문장을 구분한다.

## 7. 상품 이미지와 시각 자료

- 대표 사진은 상품 식별, 연출 사진은 사용 맥락, 확대 사진은 세부 확인을 담당한다. 모든 사진에 같은 역할을 요구하지 않는다.
- 중요한 피사체·텍스트·구성품을 보호하고 원본 비율을 유지한다. 크롭 시 의미가 달라지지 않는지 확인한다.
- 같은 상품의 조명·색감·배경 분위기를 맞추되 실제 외관과 차이를 과장하지 않는다.
- 디지털 상품은 실제 본문·파일·사용 화면을 핵심 근거로 활용한다. 목업·개념도·가상의 예시 화면은 실자료와 구분한다.
- 이미지형은 텍스트 합성을 허용하되 수정 가능한 원본을 유지한다. 배경 위 글자는 대비·복잡도·줄바꿈을 확인한다.
- 웹은 가능한 한 실제 텍스트를 사용한다. 정보 이미지의 핵심 내용은 대체 텍스트·인접 본문 등으로 전달한다.
- 비교 사진은 배율·각도·조건을 맞추고 차이를 설명한다. 아이콘은 의미가 불명확하면 짧은 이름을 함께 쓴다.
- 품질이 낮거나 없는 자료를 다른 상품 사진으로 대신하지 않는다. 필요한 자료와 제작할 자료를 구분한다.

## 8. 재사용 디자인 요소

이 장은 배치 형식을 정의한다. 모듈 선택은 3장, 사진·자료 제작은 7장을 따른다.

| --- | --- |

| 배지·강조 문구 | 짧고 확인 가능한 정보만 사용. 인증·수상으로 오인되는 장식 금지 |
| 비교표·사양표 | 비교 기준·단위·조건 표시, 같은 열의 정렬 통일, 긴 내용은 전체 확인 가능하게 구성 |
| 후기 블록 | 실제 발언·출처·필요한 맥락 구분, 인용 의미를 바꾸는 편집 금지 |
| 안내·주의 박스 | 관련 정보 가까이에 배치하고 핵심 조건은 충분한 크기로 표시 |
| 단계 설명 | 단계 수·순서·각 단계의 행동과 결과를 일관되게 표현 |

- 이미지형의 표는 모바일 축소 상태에서 읽히게 분할하거나 항목형으로 바꾼다. 이미지 내부 스크롤을 전제하지 않는다.
- 웹의 표는 필요 시 가로 스크롤을 허용하되 페이지 전체의 가로 넘침을 막는다.
- 버튼·입력 등 실제 컨트롤이 같은 가로 행에 있으면 가능한 한 높이를 맞춘다. 여러 줄 콘텐츠·접근성·세로 배치에는 강제하지 않는다. 장점 카드의 높이를 맞추려고 글을 자르지 않는다.

## 9. 웹 전용 요소와 동작

이미지형만 제작할 때 이 장의 컨트롤·인터랙션 규칙은 적용하지 않는다. 이미지에 그린 UI에 동작이 있는 것으로 간주하지 않는다.

- 버튼은 실행, 링크는 이동에 사용한다. 구매 버튼·가격·선택 옵션은 실제 판매 시스템의 값과 동작에 연결한다.
- 컨트롤의 크기·상태·라운딩은 [Carbon 컴포넌트 공식 가이드](https://carbondesignsystem.com/components/overview/)를 참고하고 승인된 브랜드 조정을 기록한다.
- 기본·포커스·선택·비활성·처리 중·실패 상태를 정의한다. 옵션 선택과 구매 요청이 중복 실행되지 않게 한다.
- 갤러리는 현재 위치·이동 경계·확대·키보드·터치 조작을 제공하고 페이지 스크롤을 방해하지 않는다.
- 펼쳐보기는 핵심 구매 조건을 숨기는 수단으로 사용하지 않는다. 로딩·실패·품절·선택 불가 상태를 구분하고 복구 방법을 제공한다.
- 고정 구매 영역이 본문과 포커스를 가리지 않게 한다. 모바일·화면 확대에서도 주요 행동에 접근할 수 있어야 한다.
- 실제 텍스트·의미 있는 구조·컨트롤 이름·포커스 순서를 제공한다. 모달을 닫으면 적절한 위치로 포커스를 돌린다.
- 모션은 이해를 지원할 때만 사용한다. 움직임 감소 설정을 존중하고 콘텐츠 열람을 애니메이션 완료에 의존시키지 않는다.

## 10. 디자인 값과 제작 규격 관리

- 공통 문서는 값의 역할과 관리 방법을 정의한다. 실제 수치·색상·폰트·출력값은 레퍼런스의 한 곳에서 관리한다.
- 관리 항목: 색상 역할, 언어별 글꼴·크기·굵기·행간·자간, 제작 폭·안전 여백·간격, 라운딩·테두리, 사진 비율, 웹 컨트롤 상태, 출력 형식·압축·분할.
- 이미지형은 원본 제작 크기·모바일 확인 크기·출력 크기를 구분한다. 웹은 분기점과 반응형 동작을 기록한다.
- 채널별 규격은 제작 시 공식 기준으로 확인하고 확인일·출처를 레퍼런스에 남긴다. 특정 플랫폼의 폭·용량 제한을 범용 기본값으로 고정하지 않는다.
- 간격과 모서리 수치를 본문 곳곳에 반복하지 않는다. Carbon 공식 수치표를 복사해 별도 기준을 만들지 않는다.

## 11. 검수와 납품 기준

### 11.1 콘텐츠·디자인 검수

- 상품명·구성·가격·단위·제공 조건이 원자료와 일치하는가? 확인 필요 항목이 확정된 문구로 섞이지 않았는가?
- 장점에 근거가 연결되고 과장·가짜 후기·허위 비교·실물 오인이 없는가?
- 고객이 상품의 쓰임·포함 항목·제약을 이해하고 구매 여부를 판단할 수 있는가?
- 제목·정렬·간격·색상·사진·반복 요소가 정의한 역할을 일관되게 따르는가?
- 각 섹션이 하나의 핵심 메시지만 전달하며, 큰 제목과 그보다 작은 추가 설명으로 구성돼 있는가? 추가 설명·예시·근거가 제목의 메시지를 뒷받침하는가?
- 중요한 조건이 충분히 보이고 모바일 표시 크기에서 본문·표·이미지 속 글자가 읽히는가?
- 텍스트 대비 목표는 일반 본문 4.5:1, 큰 텍스트 3:1을 기본으로 확인한다. 목표 충족만으로 전체 접근성을 검증했다고 하지 않는다.
- 사용한 자료·폰트·인용의 권한과 출처가 확인됐는가?

### 11.2 방식별 검수와 납품

- 이미지형: 실제 채널 미리보기에서 축소 가독성·화질·긴 이미지 분할·연결 경계·잘림·색상 차이·용량을 확인한다. 클릭 불가능한 UI를 실제 동작처럼 안내하지 않는다.
- 웹·혼합형: 작은 화면·키보드·화면 확대·로딩·오류·구매 연결·움직임 감소를 실제로 확인한다. 이미지 영역과 HTML 정보가 충돌하지 않아야 한다.
- 납품물은 편집 원본, 출력 파일, 사용 자료·출처, 검수 결과를 구분한다. 수정 가능한 원고와 디자인 값을 보존한다.
- 파일명은 섹션 순서·내용·버전을 알아볼 수 있게 정한다. 디지털 상품 자체의 제공 파일과 판매용 상세페이지 납품물을 혼동하지 않는다.
- 기획 승인·원고 확인·원본 제작·출력·실제 채널 확인을 별도 상태로 기록한다. 문서 작성만으로 상세페이지 제작·납품 완료라고 표시하지 않는다.
