# 상품 태그 2단계 검증 기록

## 개발 전용 데모

- 실행: `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort`
- 주소: http://127.0.0.1:5173/recipes/recipe/__shoppable-demo__
- 데이터: `src/dev/shoppableDemo.ts` (로컬 메모리). Firestore 읽기·쓰기 없이 데모 레시피와 상품을 공급한다. 앱 공통 인증 초기화는 기존대로 유지된다.
- 데모 진입과 상품 주입은 `import.meta.env.DEV` 조건의 동적 import로 제한한다. 프로덕션 빌드에서 데모 모듈은 제거된다.
- 구매 링크는 실제 상점이 아닌 https://example.com/ 테스트 페이지다. 결제나 주문 기능이 아니다.

사진 1에는 중앙과 좌우 가장자리에 태그 3개, 사진 2에는 태그 1개, 사진 3에는 태그가 없다. 3단계 구현 이후에는 좌우 화살표·사진 번호와 확대보기를 사용한다.

수동 확인 순서:
1. 첫 사진의 + 아이콘 3개 확인.
2. 중앙 태그에 마우스를 올리고 팝오버까지 이동. 링크 클릭 시 example.com이 새 탭으로 열리고 레시피가 유지되는지 확인.
3. 양쪽 가장자리 태그에 마우스를 올려 팝오버가 뷰포트 밖으로 잘리지 않는지 확인.
4. 브라우저 개발자 도구의 모바일 모드에서 태그 터치, 다른 태그 터치, 외부 터치 닫기 확인. 실기기 확인도 별도 필요.
5. 다음 사진 버튼으로 사진 2 전환 시 태그 1개, 사진 3 전환 시 0개 확인. 관련 상품도 함께 변경되는지 확인.

직접 브라우저 검증은 Computer Use의 Chrome 접근 권한 거부로 수행하지 못했다. 따라서 화면 가장자리의 실제 배치와 실제 모바일 터치, 구매 링크의 실제 새 탭 전환은 수동 확인이 남아 있다. 자동 테스트에서 호버/터치/키보드, 링크 속성, 사진 전환별 태그, 백분율 위치 스타일은 확인했다.

## 테스트 결과

- 관련 테스트 18개 중 17개 통과, 기존 정렬 테스트 1개 실패 재현.
- 프로덕션 `dist/assets/*.js`에서 `__demo-cup`, `__demo-plate`, `shoppableDemo`, 데모 레시피 제목 검색 결과 없음.
- UI 구조, 관리자 기능, 3단계 관련 상품 목록·새 전환 UI는 변경하지 않았다.

## 정렬 실패 분석 (수정 안 함)

`src/utils/recipeCookingGroups.ts`는 Map으로 최초 순서를 구성한 뒤 `localeCompare(..., 'ko')`로 이름순 정렬한다. 그래서 입력의 '양념장 → 반죽'이 '반죽 → 양념장'으로 바뀐다.

`tests/RecipeIngredientModes.test.tsx`의 실패 테스트는 최초 순서 유지를 기대한다. `DESIGN-tsrecipe.md` 14행 역시 '그룹과 그룹 안의 재료는 레시피에서 처음 나타난 순서를 유지한다'고 명시한다. 따라서 현재 문서 기준으로 테스트 기대값이 맞으며 함수의 이름순 정렬이 불일치다.

HEAD의 해당 함수에는 정렬이 없고 현재 작업 트리에 정렬이 추가되어 있다. 이 변경은 상품 태그 작업을 시작하기 전부터 존재한 미커밋 변경이다. 상품 태그 구현은 이 함수나 실패 테스트를 수정하지 않았다.

권장: 최초 순서를 유지하도록 `.sort(...)`를 제거한다. 이름순이 실제 의도라면 문서와 테스트를 함께 변경하는 대안이 있지만 승인 전에는 어느 쪽도 수정하지 않는다.

## Firebase 규칙 검증

새 기능에서 배포가 필요한 부분은 `firestore.rules`의 `/taggedProducts/{productId}` 규칙이다. 기존 `/recipes/{recipeId}` 관리자 쓰기 규칙이 이미지 ID 및 태그 저장에도 적용된다. 이번 단계에는 새 Storage 경로가 없으며 `storage.rules` 변경은 필요하지 않다. 향후 썸네일 파일 업로드 경로는 관리자 단계에서 검토한다.

로컬 에뮬레이터 프로젝트 `demo-shoppable-permissions`, 주소 `127.0.0.1:8089`에서 `node scripts/check-shoppable-rules.mjs` 실행 결과 전체 통과:

| 주체 | 상품 읽기·목록 | 상품 생성·수정·삭제 | 레시피 태그 쓰기 |
| --- | --- | --- | --- |
| 비로그인 | 허용 | 차단 | 차단 |
| 인증된 비관리자 | 허용 | 차단 | 차단 |
| 관리자 이메일이지만 이메일 미인증 | 허용 | 차단 | 차단 |
| 인증·이메일 확인된 관리자 | 허용 | 허용 | 허용 |

관리자에게도 잘못된 구매 URL과 음수 가격 저장은 차단됨을 확인했다. 삭제는 soft delete와 직접 삭제 모두 관리자에게 허용된다. 현재 규칙은 삭제된 상품 문서도 공개 읽기를 허용하며, 서비스에서 표시를 제외한다. 비공개 정보는 이 컬렉션에 저장하면 안 된다.

운영 배포 및 실제 계정 권한 검증은 미완료다. 승인 후 작업은 다음과 같다:
1. 운영 프로젝트 ID와 기존 규칙 전체 차이를 확인한다. 파일 단위 배포이므로 다른 미배포 변경도 포함되는지 검토한다.
2. 승인된 Firestore 규칙만 배포한다 (Hosting/Storage는 별도 승인 범위).
3. 테스트용으로 명시한 별도 문서 ID에 대해 비로그인·비관리자·관리자 실제 계정으로 권한을 확인하고 정리한다. 이 단계의 읽기 전용 데모 데이터는 운영에 올리지 않는다.
4. Firebase App Check, 실제 로그인 토큰, 네트워크 오류 등 에뮬레이터가 대체하지 못하는 운영 조건을 확인한다.

현재 운영 규칙은 조회·배포하지 않았다. 에뮬레이터 검증 결과는 로컬 파일 기준이며 운영 적용 완료를 뜻하지 않는다.

## 5단계 최종 검증 결과 (2026-10-25)

- 에뮬레이터를 포함한 전체 자동 테스트: 25개 파일, 85개 테스트 모두 통과.
- 상품 생성 → 두 레시피에서 참조 → 공용 상품 수정 → 사진 순서 변경 → 사진 교체 → 상품 삭제를 로컬 Firestore 실제 저장·재조회로 확인.
- 일반 사용자 읽기 허용, 관리자 쓰기 허용, 비관리자·이메일 미인증 관리자 쓰기 차단 확인.
- 타입 검사와 프로덕션 빌드 통과. 빌드 산출물에서 개발 전용 데모 상품 데이터 제외 확인.
- 전체 검사 중 발견한 Shop 미리보기의 이미지 탐색 코드를 `querySelectorAll('img')` 방식으로 수정. 오래된 판매형 상세페이지 테스트는 사용자가 요청한 블로그형 상세페이지 기준으로 갱신.
- 실제 브라우저·모바일 기기·스크린리더 확인은 Chrome 접근 제한으로 미완료. 자동 테스트가 실제 기기 확인을 대체하지는 않음.

마지막에 `firebase deploy --only firestore:rules --project recipes-5a663 --non-interactive`로 운영 규칙 배포를 시도했으나 저장된 CLI 인증 만료 및 토큰 갱신 실패로 HTTP 401이 발생했다. 규칙 컴파일 검사 API 호출에서 중단되었으며 운영 규칙 배포는 완료되지 않았다. 웹사이트·Storage 규칙도 배포하지 않았다.

남은 작업: 사용자가 `firebase login --reauth`로 다시 로그인한 뒤 동일한 Firestore 규칙 배포를 재실행하고 성공 응답 확인. 이후 실제 운영 계정 권한과 브라우저·모바일의 최종 확인이 필요하다.
